# SECURITY.md — модель угроз и меры (OneSTools.Ras)

Исходная модель: 2026-09-23 (TODO.md T7). Обновлена после ревизии 2026-09-25 и релизной
подготовки 2026-09-30 (комплект `tools/build-release.sh`, развёртывание — docs/DEPLOYMENT.md);
результат проверок и ограничения описаны в §3–5.

## 1. Эксплуатационное допущение (принято заказчиком)

Решение работает в **изолированном контуре**: доступ к портам RAS (1545) и ClickHouse
(8123/9000) имеют только доверенные хосты мониторинга. **TLS/SASL-шифрование не используется**
— пароли RAS и учётные данные ClickHouse передаются **открытым текстом** по протоколам SWP/HTTP.
Это accepted risk; при выходе за пределы контура — закрывать TLS на транспортной сети
(IPSec/mTLS-прокси) или доработкой START_TLS/SASL в клиенте (область TBD, см. §6).

## 2. Архитектурные границы и активы

```
[1C RAS/кластеры] --SWP:1545--> [OneSTools.Ras.Client (RasConnection/RasEndpoint/RasReader)]
                                        |
                              [Exporter.Core: коллекторы → StorageHealthGate → BatchProcessor*5]
                                        |
                              [ClickHouse HTTP:8123, bulk copy, DDL]
```

Активы: 1) учётные данные (agent/cluster-администраторы RAS, ClickHouse); 2) конфигурация
топологии (хосты, имена кластеров); 3) собираемые метрики (имена пользователей 1С, хосты
клиентов — ПДн-содержащие поля); 4) доступность самого экспортера и RAS-сервера.

Внешние входные поверхности (данные, которым доверяем меньше всего):
- **поток ответов RAS** (разбирается RasReader) — hardened;
- конфигурация (appsettings/env/local.json) — источник администратора;
- ClickHouse-ответы (DDL/SELECT 1) — фиксированные форматы.

## 3. Угрозы и меры

| # | Угроза | Вектор | Мера | Статус |
|---|--------|--------|------|--------|
| T1 | OOM/отказ клиента | повреждённый/враждебный ответ RAS: гигантские length, вложенные списки, overlong varint, deflate-бомба | `RasReader.ReadListCount` для вложенных списков, контроль переполнения varint, ограничение распакованного endpoint-сообщения 64 MiB, кадра 256 MiB, диагностической очереди (16 кадров ≤64 KiB); регрессионные тесты | **лимиты установлены** (отдельный нагрузочный тест против атакующего сервера не проводился) |
| T2 | StackOverflow-краш | бесконечная цепочка `cause` в сериализованном throwable | глубина ≤32 (`MaxThrowableDepth`) | **закрыто** (S1) |
| T3 | Деградация до отказа (утечка памяти) | ClickHouse лежит → очереди метрик растут бесконечно | `StorageHealthGate`: пауза опросов, зонд каждые 30 c; `BoundedChannel(100k, Wait)`; повторная инициализация схемы до старта сбора; повтор записи лишь неудачных групп | **ограничено**: после исчерпания попыток потери учитываются в `DroppedItems` и health-check (best effort) |
| T4 | SQL/DDL-инъекция через имя кластера 1С | clusterName → имя БД в backtick-интерполяции DDL | Slugify (кириллица→латиница, `[a-z0-9_]`), вторичный `ValidateDatabaseName` (гейт `[a-z0-9_]{1,128}` на всех DDL/write-путях), данные — только через `ClickHouseBulkCopy` (типизированные строки) | **закрыто** (S4 + инъекционные тесты) |
| T5 | Раскрытие секретов | логи/health-описания/конфиг в репозитории | `appsettings.json` без пароля ClickHouse; devcontainer требует `CLICKHOUSE_PASSWORD` извне, хостовые dev-порты слушают только `127.0.0.1`; боевые креды — env или `appsettings.local.json` (gitignored, приоритет base<local<user-secrets<env<args) | **ограничено настройкой окружения** |
| T6 | Компрометация зависимостей | уязвимые NuGet-пакеты (прямые/транзитивные) | `NuGetAudit=all/low`, `packages.lock.json`, locked-mode restore, разбор JSON-отчёта `dotnet list package --vulnerable --include-transitive` через `jq`; тестовый отчёт с уязвимым пакетом должен давать FAIL. Отдельно: restore с `RuntimeIdentifier` (self-contained publish) раскрывает легаси-граф netstandard1.x с `System.Private.Uri 4.3.0` (GHSA-xhfc-gr8f-ffwc) — пин 4.3.2 в `Directory.Build.props` только для RID-графа; `tools/build-release.sh` восстанавливает `packages.lock.json` и завершает сборку RID-agnostic `restore --locked-mode`, чтобы аудит не проверял чужой граф | **закрыто процессом** (повторять сканирование при обновлениях) |
| T7 | SSRF/произвольный egress | конфигурация задаёт хосты RAS/CH | доверенный конфигуратор = граница; исходящих URL из данных RAS нет (внутренние адреса кластеров не адресуются, только имя+порт административно) | **ограничено архитектурно** |
| T8 | Лавина переподключений (отказ RAS от мониторинга) | flap RAS/CH → reconnect-storm | экспоненциальный `BackoffPolicy` 1→60 c с jitter, сброс на успех | **закрыто** (T2-ревизия, 244b5d1) |
| T9 | Разрыв десинхронизации протокола | cancel после отправки запроса → «осиротевший» ответ будет принят за следующий запрос | автозакрытие соединения при cancel-after-send; `IsClosed` → реконнект | **закрыто** (T1-ревизия) |
| T10 | Неавторизованный запуск dev-инструментов в проде | MockServer/LoadSim слушают/подключаются | вне состава прода; только devcontainer. Не деплоить | **документировано** |
| T11 | Чрезмерные права учётных записей | admin RAS/CH «под всё» | минимизация: см. чек-лист §5 | **чек-лист** |

## 4. Что намеренно НЕ закрыто (accepted)

- Plaintext SWP/HTTP (см. §1) — только в изолированном контуре.
- Экспорт метрик best effort: при длительном сбое хранилища метрики во время паузы не собираются;
  после исчерпания повторов батч отбрасывается с записью ошибки и счётчика. Устойчивой к
  перезапуску очереди и гарантии exactly-once нет.
- SASL (PLAIN/DIGEST-MD5/…), START_TLS — транспортом не реализованы (не требуются в контуре).
- Аудит/экспорт самих метрик (ПДн в сессиях) — ретенция и доступ к ClickHouse на совести оператора.
- EOL .NET 8 (ноябрь 2026) — по решению заказчика игнорируется; миграция на LTS не запланирована.

## 5. Чек-лист перед ИБ-аудитом / вводом в эксплуатацию

- [ ] В `bin/appsettings.json` (рядом с бинарником) нет паролей; учётные данные заданы через
      `bin/appsettings.local.json`/env.
- [ ] Учётка RAS-агента: только права мониторинга (не глобальный admin, если platform это позволяет).
- [ ] ClusterUser: минимум для `getSessionList/processList/connectionList/lockList`.
- [ ] ClickHouse-пользователь: `GRANT` только на `ras_cluster_%` (INSERT, CREATE для авто-схем), не global.
- [ ] Сегментация: доступ к 1545/8123 только с хостов мониторинга (firewall/NACL).
- [ ] Для devcontainer установлен `CLICKHOUSE_PASSWORD`; опубликованные порты ограничены loopback.
- [ ] `bash tools/security-check.sh` — PASS на целевой машине.
- [ ] Логи экспортёра не содержат паролей; health-описания содержат только тексты ошибок соединений.
- [ ] `MockServer`/`LoadSim` отсутствуют в прода-развёртывании.
- [ ] Ротация паролей: конфиг обновляется env/local.json, рестарт службы (без пересборки).
- [ ] Оповещения: `Health: Degraded/Unhealthy` (ошибки/давность опросов и счётчик потерянных
      метрик) подключены к мониторингу.
- [ ] Комплект собран `bash tools/build-release.sh` (все гейты зелёные), перенесённый архив
      проверен по `SHA256SUMS.txt`; в релизе нет `appsettings.json` со стендовыми хостами/UUID —
      конфигурация создаётся из `appsettings.production.example.json` на целевом сервере.
- [ ] Файл с секретами недоступен посторонним: Linux `0640 root:rasexporter` на
      `/etc/onestools/ras-exporter/*.env`, Windows — ACL на `appsettings.local.json`;
      служба под выделенным непривилегированным аккаунтом (`User=rasexporter`, `nologin`).

## 6. Рекомендации по развитию (не блокеры аудита)

- TLS/SASL в клиенте — при выходе за изолированный контур (TRANSPORT_SPEC §5–6: протокол поддерживает;
  на wire это SASL-фреймы 5–10 и START_TLS=3, плюс `docs/TRANSPORT_SPEC.md §9.2` — непроверенные области).
- Rate-limit опросов per-cluster уже есть через таймеры; при масштабировании — jitter расписания.
- Включение `AnalysisLevel` security-анализаторов (CA21xx/CA5xxx) — после закрытия T3-комментариев.
