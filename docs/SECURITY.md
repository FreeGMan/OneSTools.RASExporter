# SECURITY.md — модель угроз и меры (OneSTools.Ras)

Дата: 2026-09-23 (TODO.md T7). Актуально для версии после коммитов e2de40e…760337f.

## 1. Эксплуатационное допущение (принято заказчиком)

Решение работает в **изолированном контуре**: доступ к портам RAS (1545) и ClickHouse
(8123/9000) имеют только доверенные хосты мониторинга. **TLS/SASL-шифрование не используется**
— пароли RAS и учётные данные ClickHouse передаются **открытым текстом** по протоколам SWP/HTTP.
Это accepted risk; при выходе за пределы контура — закрывать TLS на транспортной сети
(IPSec/mTLS-прокси) или доработкой START_TLS/SASL в клиенте (область TBD, см. §6).

## 2. Архитектурные границы и активы

```
[1C RAS/кластеры] --SWP:1545--> [OneSTools.Ras.Client (RasConnection/RasEndpoint/RasReader)]
                                        |
                              [Exporter.Core: коллекторы → StorageHealthGate → BatchProcessor*5]
                                        |
                              [ClickHouse HTTP:8123, bulk copy, DDL]
```

Активы: 1) учётные данные (agent/cluster-администраторы RAS, ClickHouse); 2) конфигурация
топологии (хосты, имена кластеров); 3) собираемые метрики (имена пользователей 1С, хосты
клиентов — ПДн-содержащие поля); 4) доступность самого экспортера и RAS-сервера.

Внешние входные поверхности (данные, которым доверяем меньше всего):
- **поток ответов RAS** (разбирается RasReader) — hardened;
- конфигурация (appsettings/env/local.json) — источник администратора;
- ClickHouse-ответы (DDL/SELECT 1) — фиксированные форматы.

## 3. Угрозы и меры

| # | Угроза | Вектор | Мера | Статус |

## 4. Что намеренно НЕ закрыто (accepted)

- Plaintext SWP/HTTP (см. §1) — только в изолированном контуре.
- SASL (PLAIN/DIGEST-MD5/…), START_TLS — транспортом не реализованы (не требуются в контуре).
- Аудит/экспорт самих метрик (ПДн в сессиях) — ретенция и доступ к ClickHouse на совести оператора.
- EOL .NET 8 (ноябрь 2026) — по решению заказчика игнорируется; миграция на LTS не запланирована.

## 5. Чек-лист перед ИБ-аудитом / вводом в эксплуатацию

- [ ] В `appsettings.json` нет боевых паролей (только dev-плейсхолдеры; `appsettings.local.json`/env).
- [ ] Учётка RAS-агента: только права мониторинга (не глобальный admin, если platform это позволяет).
- [ ] ClusterUser: минимум для `getSessionList/processList/connectionList/lockList`.
- [ ] ClickHouse-пользователь: `GRANT` только на `ras_cluster_%` (INSERT, CREATE для авто-схем), не global.
- [ ] Сегментация: доступ к 1545/8123 только с хостов мониторинга (firewall/NACL).
- [ ] `bash tools/security-check.sh` — PASS на целевой машине.
- [ ] Логи экспортёра не содержат паролей; health-описания содержат только тексты ошибок соединений.
- [ ] `MockServer`/`LoadSim` отсутствуют в прода-развёртывании.
- [ ] Ротация паролей: конфиг обновляется env/local.json, рестарт службы (без пересборки).
- [ ] Оповещения: `Health: Degraded/Unhealthy` (лог-паблишер) подключены к мониторингу.

## 6. Рекомендации по развитию (не блокеры аудита)

- TLS/SASL в клиенте — при выходе за изолированный контур (TRANSPORT_SPEC §5–6: протокол поддерживает;
  на wire это SASL-фреймы 5–10 и START_TLS=3, плюс `docs/TRANSPORT_SPEC.md §9.2` — непроверенные области).
- Rate-limit опросов per-cluster уже есть через таймеры; при масштабировании — jitter расписания.
- Включение `AnalysisLevel` security-анализаторов (CA21xx/CA5xxx) — после закрытия T3-комментариев.
